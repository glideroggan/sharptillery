# Sharptillery 0.6.0

- **Right counts.** A request cut off at the end of a phase is counted as "cancelled at phase end", not as a 500. The error ratio and "% done" are per phase.
- **New run loop, no busy core.** Clients write results to a bounded channel that the run awaits with a 1 s timer. A `-c 8 -d 5s` run against a 500 ms endpoint went from 5.8 s to under 1 s of tool CPU.
- **Input checks and YAML narrowed.** Headers, `-m`, `-e`, `-b` and auto-tune values are checked at parse time, and YAML holds only what runs. Bad input fails with a clear message before the run starts.
- **Less memory.** A 60 s HTML run went from about 1.4 GB to about 0.4 GB.
- **HTML report works offline.** Chart.js 4.5.1 is bundled in the tool.
- **`-e csv` added.** One row per request, written as the run reads its results.
- **`-e excel` removed (breaking).** Scripts that pass `-e excel` must use `-e csv` or `-e html`.
- **`-r` hits its target.** The clients of a phase share one schedule, so the rate is reached instead of drifting low. A phase that cannot keep up reports the rate it reached.
